3. How data gets there

Input.txt  →  validate  →  Kafka topic  →  Kafka Streams (exactly_once_v2)
                                              ↓
                         Output.csv  ←  aggregate by client|product
                                              ↓
                         GET /api/summary  and  GET /api/summary.csv
                                              ↓
                         Angular table (5s poll) + CSV download

Malformed records skip the totals and go to the dead-letter topic. The file is append-only; truncation/rewrite is treated as an operational error.

4. How to use the API

Same report, two representations. JSON for the UI; CSV for Excel/download.

curl http://127.0.0.1:18081/api/summary
curl -OJ http://127.0.0.1:18081/api/summary.csv

# Through the frontend proxy (nginx → backend):
curl http://127.0.0.1:18080/api/summary

This boot returned HTTP 200, Content-Type: text/csv, and Content-Disposition: attachment; filename="Output.csv".

5. How to boot it yourself

  1. Need Java 21, Maven, Node, an external Kafka cluster, and Docker if you want containers.
  2. Backend: mvn -f backend/pom.xml package then run the Spring Boot app with INPUT_FILE, OUTPUT_FILE, and KAFKA_BOOTSTRAP_SERVERS pointed at your files and Kafka.
  3. Frontend: npm --prefix frontend ci && npm --prefix frontend start — the dev server proxies /api to localhost:8080.
  4. Containers: build both images (see README), then kubectl apply -f k8s/ after Kafka exists. This demo used one backend replica, a PVC at /data, and Kafka as an external service.
  5. Drop or append records on Input.txt. Wait a few seconds. The table refreshes; CSV download matches JSON.
